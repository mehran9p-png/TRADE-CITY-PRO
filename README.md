# TCP Radar (`TRADE-CITY-PRO`)

**TCP Radar** یک وب‌اپلیکیشن آموزشی و متن‌باز (Client-Side PWA) برای بررسی ساختار بازار (سقف‌ها و کف‌های پیوت)، میانگین‌های متحرک (`SMA 7, 25, 99`)، شاخص‌های مومنتوم (`RSI`, `DMI/ADX`, `ROC`)، تجمیع پله‌ای دفتر سفارشات (Order Book)، محاسبه حجم مجاز پوزیشن و ثبت ژورنال معاملاتی است.

> **سلب مسئولیت مهم (هشدار ریسک):** این نرم‌افزار صرفاً یک ابزار آموزشی و محاسباتی است و تحت هیچ شرایطی توصیه مالی، سیگنال خرید یا فروش، یا تضمین سود محسوب نمی‌شود. معامله در بازارهای مالی و به‌ویژه قراردادهای فیوچرز با اهرم (Leverage) ریسک بسیار بالایی دارد و می‌تواند منجر به از دست رفتن کامل سرمایه شود. نتایج بک‌تست روی کندل‌های گذشته هیچ تضمینی برای عملکرد آینده بازار نیستند.

## ۱. جدول شفافیت داده‌ها و متریک‌ها (هر متریک از کجا می‌آید و چقدر قابل اعتماد است؟)

برای جلوگیری از هرگونه ابهام، منبع و سطح دقت هر متریک در جدول زیر مشخص شده است:

| متریک / بخش | منبع داده در حالت آنلاین | وضعیت دقت (زنده / محاسبه‌شده / تخمینی) | توضیح فنی و محدودیت‌ها |
| :--- | :--- | :--- | :--- |
| **قیمت لحظه‌ای و کندل‌ها (`OHLCV`)** | وب‌سوکت و REST صرافی‌ها (`Bybit V5` ⬅ `OKX V5` ⬅ `Binance`) | **زنده (Live)** | در صورت مسدود بودن هر سه صرافی روی شبکه کاربر، بنر قرمز «غیرزنده / آفلاین» فعال شده و ثبت سفارش/ژورنال/آلارم قفل می‌شود (تیک تصادفی تولید نمی‌شود). |
| **میانگین‌های متحرک (`SMA 7, 25, 99`)** | کلوز کندل‌های دریافت‌شده | **محاسبه‌شده دقیق (Calculated)** | میانگین حسابی ساده روی ۷، ۲۵ و ۹۹ کندل اخیر تایم‌فریم انتخابی. |
| **شاخص `RSI` و طول نیم‌سایکل** | کلوز کندل‌ها و فاصله پیوت‌های کف | **محاسبه‌شده (Calculated)** | فرمول استاندارد Wilder's RSI؛ طول دوره در حالت Auto برابر نصف میانگین فاصله کف‌های ماژور (گردشده به عدد زوج در بازه ۸ تا ۳۶) است. |
| **شاخص‌های `DMI (+DI/-DI)`، `ADX` و `ROC`** | سقف، کف و کلوز کندل‌های واقعی | **محاسبه‌شده دقیق (Calculated)** | محاسبه واقعی `True Range (TR)`، `+DM`، `-DM` و هموارسازی Wilder در دوره ۱۴؛ `ROC` روی دوره ۱۰ کندل. |
| **تفکیک حجم خریدار و فروشنده (`Taker Buy / Sell`)** | در بایننس: فیلد `k[9]` کندل؛ در بای‌بیت/OKX: تخمین از محل کلوز کندل | **زنده در بایننس / تخمینی در Bybit و OKX** | API عمومی کندل‌های Bybit و OKX فیلد `TakerBuyVolume` را جداگانه در خروجی `kline` برنمی‌گرداند؛ بنابراین زمانی که منبع روی Bybit یا OKX است، سهم خریدار بر اساس محل بسته شدن کندل در بازه `High-Low` تخمین زده می‌شود و در رابط کاربری برچسب `تخمینی` می‌خورد. |
| **دفتر سفارشات تجمیعی (`Order Book`)** | REST API عمق بازار (`limit=200` تا `500`) | **زنده و تجمیع‌شده در پله‌های قیمتی** | سفارشات واقعی دریافت‌شده در بازه‌های قیمتی (`0.1%`, `0.25%`, `0.5%`) حول قیمت لحظه‌ای جمع زده می‌شوند. در صورت عدم دسترسی به API عمق بازار، جدول خالی مانده و وضعیت غیرزنده اعلام می‌شود. |
| **دامیننس‌ها (`BTC.D`, `USDT.D`, `TOTAL2`)** | API عمومی `CoinGecko (/api/v3/global)` | **زنده با کش کوتاه‌مدت / شبیه‌ساز آموزشی** | در صورت محدودیت نرخ درخواست (Rate Limit) در CoinGecko، آخرین مقدار کش‌شده نمایش داده می‌شود و کاربر می‌تواند با دکمه‌های شبیه‌ساز آموزشی، سناریوهای مختلف دامیننس را تمرین کند. |
| **احتمال زنجیره ضرر (`Losing Streak`)** | ورودی وین‌ریت کاربر | **محاسبه‌شده ریاضی دقیق (Markov DP)** | محاسبه دقیق احتمال رخداد حداقل $k$ باخت متوالی در $n$ معامله مستقل با برنامه‌نویسی پویا (مثلاً برای وین‌ریت ۵۲٪ در ۱۰۰ معامله و $k=5$: دقیقاً `75.0%` و برای وین‌ریت ۵۰٪: دقیقاً `81.0%`). |
| **قیمت لیکوئید شدن و حداکثر اهرم مجاز** | فرمول مارجین ایزوله با حاشیه نگهداری (`MMR = 0.5%`) | **محاسبه‌شده تقریبی (تخمینی)** | قوانین دقیق لیکوئید شدن به پله‌های مارجین (Tiered Maintenance Margin) هر صرافی بستگی دارد. سقف اهرم پیشنهادی در این ابزار حداکثر `20x` محدود شده و در صورت قرار گرفتن قیمت لیکوئید قبل از حد ضرر، هشدار صریح نمایش داده می‌شود. |

## ۲. محدودیت‌های شناخته‌شده (Known Limitations)

1. **محدودیت‌های شبکه و دسترسی منطقه‌ای (CORS / Geo-blocking):** این برنامه کاملاً در مرورگر کاربر (Client-Side) اجرا می‌شود. دسترسی به API صرافی‌های `Bybit`، `OKX`، `Binance` یا `CoinGecko` به وضعیت شبکه و کشور کاربر بستگی دارد و هیچ تضمینی برای عبور از محدودیت‌های منطقه‌ای وجود ندارد.
2. **عدم وجود سرور پس‌زمینه برای آلارم‌ها:** آلارم‌های قیمتی فقط زمانی کار می‌کنند که تب مرورگر یا وب‌اپلیکیشن (PWA) باز و به اینترنت متصل باشد. با بستن کامل مرورگر، پایش قیمت متوقف می‌شود.
3. **محدودیت بک‌تست درون‌مرورگری:** موتور بک‌تست صرفاً روی ۱۲۰ کندل اخیر دریافت‌شده در حافظه مرورگر اجرا می‌شود، اسلیپیج (Slippage) و نوسانات داخل کندل (Intra-bar ticks) را شبیه‌سازی نمی‌کند و جایگزین موتورهای بک‌تست حرفه‌ای نیست.
4. **نگهداری داده‌ها در `localStorage`:** ژورنال معاملاتی، آلارم‌ها و وضعیت قفل انضباطی در حافظه محلی مرورگر (`localStorage`) ذخیره می‌شوند. پاک کردن کش مرورگر باعث حذف آن‌ها می‌شود؛ بنابراین از دکمه **«پشتیبان‌گیری JSON»** در تب پنجم استفاده کنید.

## ۳. راهنمای استقرار (Deploy) روی GitHub Pages (`TRADE-CITY-PRO`)

1. یک ریپازیتوری عمومی (Public) با نام `TRADE-CITY-PRO` در گیت‌هاب بسازید.
2. تمام فایل‌های این پکیج (`index.html`, `manifest.json`, `sw.js`, `icon.svg`, `tailwind.config.js`, `input.css`, `.nojekyll`, `README.md`) را در شاخه `main` (پوشه ریشه `/`) آپلود و Commit کنید.
   - فایل `.nojekyll` در پکیج قرار دارد تا GitHub Pages فایل‌های استاتیک را بدون پردازش Jekyll سرو کند.
3. در ریپازیتوری به **Settings** ⬅ **Pages** بروید و در بخش **Build and deployment**، گزینه Source را روی `Deploy from a branch`، شاخه `main` و پوشه `/ (root)` قرار داده و **Save** را بزنید.
4. وب‌اپلیکیشن در آدرس زیر در دسترس خواهد بود:
   `https://<YOUR-GITHUB-USERNAME>.github.io/TRADE-CITY-PRO/`

### کامپایل محلی Tailwind CSS (اختیاری برای محیط Production)
فایل `index.html` به صورت پیش‌فرض برای اجرای فوری بدون نیاز به ابزار بیلد، اسکریپت CDN تیلویند را بارگذاری می‌کند، اما فایل‌های `tailwind.config.js` و `input.css` نیز در مخزن قرار داده شده‌اند. برای کامپایل استاتیک CSS می‌توانید دستور زیر را اجرا کنید:

```bash
npx tailwindcss -i ./input.css -o ./dist/output.css --minify
```
سپس در `index.html` تگ `<link rel="stylesheet" href="./dist/output.css">` را جایگزین اسکریپت CDN کنید.
